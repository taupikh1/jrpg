## 2. Audio architecture

```
core/ports/AudioPort.js            contract (unlock, preload, playOneShot, startLoop, setLoopGain, stopLoop, suspend, resume, getFailedPaths)
engine/audio/AudioCatalog.js       which sound/ambience is used where (pure data, no browser APIs)
engine/audio/AudioManager.js       policy: unlock gate, independent SFX/ambience volumes, mute, cooldown, one ambience at a time, holds
engine/audio/AudioEventBridge.js   EventBus -> AudioManager mapping (listen-only)
platform/browser/WebAudioAdapter.js        Web Audio implementation + installUnlockOnGesture()
platform/browser/AudioSettingsStore.js     localStorage persistence (key jrpg.audio.settings.v1)
```

Key behaviours:

- **Unlock gate:** nothing plays until a user gesture unlocks audio. `installUnlockOnGesture` listens on `pointerdown`, `touchend`, and `keydown` in the capture phase, and removes its listeners only after unlock succeeds. `AudioContext.resume()` is called synchronously inside the gesture.
- **Non-blocking loads:** all 46 assets are decoded in the background after unlock. A sound that is not decoded yet is skipped, never queued.
- **Voice cap:** at most 16 simultaneous one-shots. Extra sounds are dropped.
- **Cooldown:** the same SFX id cannot retrigger within 40 ms (rapid taps, repeated events). A refused start does not record a cooldown.
- **Ambience:** one track at a time. Switching crossfades inside the adapter. Holds (`pause`, `battle`) silence the loop without forgetting it, and release restores it.
- **Failure handling:** missing or undecodable files are recorded in `getFailedPaths()` and never throw. A failed loop can be requested again.
- **Stale loads:** if a track is replaced while still loading, the late result is ignored.

## 3. Implemented sound effects

Generated by `tools/audio/generate-audio.py`: 40 files in `assets/audio/sfx/`.

| Category | Sound ids | Triggered by |
|---|---|---|
| Menu/UI | `ui_select`, `ui_confirm`, `ui_cancel`, `ui_open`, `ui_close`, `ui_notify`, `ui_error`, `ui_save_ok`, `ui_save_fail` | Cursor index actually changed; confirm/cancel; pause, inventory, quest open/close; `save.written` event; save failure in scene; main menu selection/confirm |
| Quest / reward | `quest_accept`, `quest_complete`, `reward` | `quest.accepted`; `quest.completed` (`reward` only if rewards exist) |
| Items | `item_pickup`, `item_use` | `inventory.item_added`; `inventory.item_used` |
| Exploration | `footstep_1..3`, `npc_talk`, `zone_enter`, `examine` | Walking distance (14 px per step, no steps when still); `dialogue.started`; zone transition; `examine` is **generated but not yet wired** (no event exists for examining objects) |
| Combat | `battle_start`, `attack_physical`, `impact_weapon`, `enemy_attack`, `damage_player`, `damage_enemy`, `magic_cast`, `heal`, `defend`, `enemy_defeat`, `party_ko`, `battle_victory`, `battle_defeat`, `battle_escape` | `battle.*` events and `battle.action_resolved` (attack / skill / item / defend) |
| Progression | `exp_gain`, `level_up`, `stat_up`, `skill_unlock` | Generated and registered only. **Not triggered**, as required by this batch. |
| Status effects | `status_apply`, `status_recover` | Generated and registered. **Not triggered**: `BattleManager` has no status-effect events. |

Notes:
- Physical, magical, and healing attacks use different sounds (`attack_physical`, `magic_cast`, `heal`). Heal and magic skills are mapped from `SKILL_KIND_BY_ID` in the scene.
- Footstep variants never repeat back-to-back (tested).
- A single battle action may play two cues (swing then hit). The hit is delayed slightly, and the cooldown prevents stacking.

## 4. Implemented ambient sounds

Six seamless loops, 10 s each, built with FFT-domain synthesis so every periodic component completes whole cycles.

| Track | Zones (from `content/world` registry, all `playable`) |
|---|---|
| `village_breeze` (wind + soft stream layer) | `village` |
| `forest_wind` (wind + leaves) | `forest` |
| `road_wind` | `road_bellhaven` |
| `town_murmur` | `bellhaven_gate`, `bellhaven_plaza`, `bellhaven_market` |
| `archive_room_tone` | `bellhaven_archive_hall`, `bellhaven_archive_stacks`, `bellhaven_archive_restricted` |
| `ancient_hum` (low drone with 1 Hz beating, no melody) | `resonance_ancient_site` |

- No new locations were invented. The test suite asserts that every ambience mapping is a real zone and that every playable zone has an assignment.
- Ambience is about −25 dB RMS, subtle relative to SFX (peaks around −3 dBFS).
- Rain and weather ambience were **not added**: no zone in the current world has a weather condition.
- Zones without a mapping are silent. Entering one stops the previous ambience.

## 5. Asset inventory and licensing

- All 46 files (40 SFX, 6 ambience) were **generated by project code** (`tools/audio/generate-audio.py`) using sine and noise synthesis. No third-party samples, no commercial game audio, no Ni no Kuni material.
- They are original works covered by the project license.
- Format: MP3, mono, 64 kbps, 22.05 kHz. MP3 was chosen for iOS Safari compatibility. OGG was not added.
- Total size: 680 KB.
- Regenerate with `python3 tools/audio/generate-audio.py` (needs numpy and ffmpeg with libmp3lame). Output is deterministic.
- Known caveat: MP3 encoder padding may add a very small gap at the ambience loop seam. This was **not verified by ear** (see section 10).

## 6. Audio settings and persistence

- **Deviation:** no settings screen existed. A small **Pengaturan Audio** sub-screen was added to the pause menu, between "Simpan Permainan" and "Kembali ke Menu Utama". This avoids creating a second settings system.
- Controls: Efek suara (0–100%, 10% steps), Ambience (0–100%), Senyap (on/off), Tes efek suara, Tes ambience, Kembali.
- Left/Right adjust volume (clamped). Enter or tap cycles volume (wraps). Mute toggles. Test SFX plays a confirm cue. Test ambience previews the current zone's track (or `village_breeze`) for 4 seconds, even while paused.
- Changes apply immediately: the ambience gain is ramped live, and the next SFX uses the new volume.
- Persistence: `localStorage` key `jrpg.audio.settings.v1`, separate from IndexedDB save slots. The store writes only `sfxVolume`, `ambientVolume`, and `muted` (tested). Corrupt or missing values fall back to defaults. Storage errors never crash audio.
- Save data is not touched by audio changes. Browser verification confirmed settings survive a page reload.
- Defaults: SFX 80%, ambience 50%, not muted.

## 7. Mobile browser compatibility

Implemented:
- Audio context created and resumed synchronously inside the first gesture (`pointerdown`, `touchend`, `keydown`).
- No autoplay: nothing starts before unlock (tested at manager level, adapter level, and in the browser).
- Suspended contexts are not used for playback (adapter returns false).
- `main.js` calls `audio.suspend()` when the page is hidden and `audio.resume()` when visible.
- Rapid taps and repeated commands are throttled by the cooldown.
- Audio never blocks gameplay: decode is background, and playback failure returns false.
- Touch controls are unchanged. Audio does not use the touch layer.

Not verified (see section 10): real iOS Safari, real Android Chrome, the hardware silent switch, background/foreground transitions on devices, and audible output quality.

## 10. Known limitations and missing assets

Missing integration (no game event exists yet):
- Doors, opening/closing doors: no door event in the code.
- Treasure chests and picking objects from the world: no chest event.
- Examining important objects (`examine` is generated, not wired).
- Story-object activation: no dedicated event.
- Battle victory reward sound: the battle reward is applied in `_updateBattle` without an event, so only `battle_victory` plays. A dedicated `reward` cue at battle reward time is not wired.
- Status effect apply and recover: `BattleManager` has no status system.
- EXP, level-up, stat-up, skill-unlock: deliberately not triggered (out of scope). Assets are ready.
- Weather or rain ambience: no weather exists in the world data.

Other limitations:
- **Physical devices:** no real iPhone or Android device was used. Mobile results are emulation only.
- **Loop seam:** MP3 padding may add a tiny gap. Not verified by ear.
- **Settings UI placement:** a pause-menu sub-screen, not a separate main-menu Settings screen (none existed).
- **Ambience during dialogue:** continues at normal volume. Ambience is held only for pause and battle.
- **First-gesture sound:** the very first key or tap that unlocks audio may not play its own sound, because output starts asynchronously. The next sound plays normally (observed in the browser run).
- **Offline caching:** audio files are cached by the existing service worker's runtime fallback on first fetch. Offline playback was not tested. `service-worker.js` was not changed.
- **Batch 9.2 P1 items D1–D4:** unresolved and outside audio scope.

## 12. Confirmation: no background music

- No music or soundtrack file exists anywhere in the project. `assets/audio/` contains only `sfx/` (40 files) and `ambient/` (6 files).
- No code path calls a music or BGM channel. The only looping channels are `ambient` (environmental) and `preview` (Tes ambience, 4 seconds).
- Enforced by tests: catalog ids are checked for music terms, asset folders must match the catalog exactly, and the generator source is scanned for music terms.
- The ambience loops contain only noise-based environmental material and a low drone with slow beating. They do not contain melodies, rhythms, or musical sequences.
